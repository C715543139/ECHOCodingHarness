# ADR-0008：模型回答的安全 Markdown 渲染

> 状态：Accepted
>
> 日期：2026-08-31
>
> 接受日期：2026-08-31
>
> 决策者：项目维护者

## 1. 背景

Web Chat 已显示聚合后的模型正文，但此前始终按纯文本渲染。Coding Agent 的回答通常包含标题、列表、
引用、表格、链接和代码块；纯文本会降低长回答与验证结果的可读性。模型输出同时属于不可信输入，
Markdown 支持不得引入脚本执行、原始 HTML 注入或自动的外部资源请求。

## 2. 决策

- 仅聚合后的模型回答使用 Markdown；用户消息、工具摘要、审批、状态和 Trace 继续使用现有纯文本或
  结构化组件；
- 使用锁定版本的 `react-markdown` 与 `remark-gfm`，支持 CommonMark 及 GFM 表格、任务列表、删除线
  和自动链接；不引入完整富文本编辑器或语法高亮框架；
- 启用 `skipHtml`，不启用 `rehype-raw`，也不使用 `dangerouslySetInnerHTML`；模型返回的原始 HTML
  不进入 DOM；
- 链接只允许相对地址、锚点、`http`、`https` 与 `mailto`，并在新标签页以
  `noopener noreferrer` 打开；
- Markdown 图片不触发网络加载，只显示包含 alt 文本的占位说明；
- 流式正文继续原位更新同一个响应记录。每次渲染当前聚合文本，刷新后仍只读取 Session 聚合事实。

## 3. 选择理由

成熟的 Markdown AST 渲染器能正确处理嵌套结构、转义和不完整流式文本，也避免维护自制正则解析器。
GFM 覆盖 Coding Agent 最常用的表格与任务列表。关闭 HTML 和图片加载后，渲染能力不会扩大本地 Web
控制台的执行边界或静默网络访问面。

## 4. 被考虑但未采用的方案

- 自制 Markdown 解析器：边界条件多，难以可靠覆盖嵌套、转义和流式不完整输入；
- 直接注入 HTML：无法接受不可信模型输出带来的 XSS 风险；
- 启用原始 HTML 或远程图片：增加 DOM 注入与跟踪请求风险；
- 同时渲染用户消息：用户气泡的目标是忠实显示输入，不应改变原始文本语义；
- 引入语法高亮器：增加体积与语言包维护成本，当前阶段收益不足。

## 5. 后果

- Web 产物增加 Markdown 解析依赖与相应体积；依赖继续由 lockfile、构建和制品 smoke 固定；
- Chat 样式需要约束标题、列表、引用、代码、表格和链接，长内容不得扩大页面级滚动；
- 组件测试必须证明模型 Markdown 产生语义 DOM、用户 Markdown 保持纯文本、原始 HTML 被丢弃且图片
  不生成网络资源元素。

## 6. 重新评估触发条件

- 需要可信的本地图片附件或受控资源代理；
- 需要代码语法高亮、复制按钮或可交互图表；
- Markdown 解析成为长流式回答的已测性能瓶颈；
- 需要允许一组经过消毒的 HTML 子集。
