# ECHO Harness 安全模型

> 状态：Proposed
>
> 版本：0.1
>
> 最后更新：2026-08-27

## 1. 文档目的

ECHO Harness 会根据模型输出读取文件、修改代码并启动本地进程。本文件定义首个版本的威胁模型、信任边界与强制控制，目标是在开发工作区内提供可审查的自动化能力。

ECHO 是开发工具，不是恶意代码分析沙箱。安全设计降低误操作和信息泄露风险，但不等价于虚拟机、容器或操作系统访问控制。

## 2. 需要保护的资产

- 工作区内的源代码、测试和配置；
- 工作区外的用户文件与系统文件；
- 模型 API Key、Git 凭据和其他环境变量；
- Git 历史与未提交修改；
- 本机进程、网络身份和外部服务；
- 会话记录、演示材料和双盲身份信息；
- 用户时间与 API 调用额度。

## 3. 信任边界

### 3.1 受信任

- 用户明确输入的目标和审批；
- ECHO 自身经过测试的 Orchestrator、安全策略与工具实现；
- 启动时确定的工作区根目录；
- 本地显式配置，但其中的密钥仍按敏感数据处理。

### 3.2 不受信任

- 模型生成的文本、工具名和所有工具参数；
- 仓库文件内容，包括 README、注释和提示注入文本；
- 命令输出、测试输出与第三方包脚本；
- OpenAI-compatible 服务返回的非预期字段；
- 符号链接、目录联接和运行中发生变化的文件系统结构；
- 被执行程序产生的子进程、网络请求和文件访问。

任何“来自模型”或“来自仓库”的操作指令都必须经过相同的校验与策略判断。

## 4. 主要威胁

| 威胁 | 示例 | 首版控制 |
| --- | --- | --- |
| 路径逃逸 | `..\\..`、绝对路径、UNC 路径 | 规范化、真实路径检查、工作区边界硬拒绝 |
| 链接逃逸 | 工作区内链接指向外部目录 | 解析现有父路径与链接目标后复检 |
| 破坏性修改 | 批量覆盖、清空目录、重写 Git 历史 | 工具限制、命令分类、审批或硬拒绝 |
| 命令注入 | 模型构造复合 PowerShell 命令 | 命令规范化、危险特征检测、非交互执行、审批 |
| 密钥泄露 | 打印环境变量、把 Key 写入日志 | 最小子进程环境、脱敏、日志禁入、输出扫描 |
| 提示注入 | 仓库文件要求上传秘密或越权 | 仓库内容不受信任，系统策略优先且不可覆盖 |
| 无限循环 | 重复读写或相同命令 | 最大 Step、重复调用检测、超时与取消 |
| 输出耗尽 | 递归列表、无限日志 | 字符/字节上限、头尾保留、明确截断 |
| 子进程残留 | 超时后测试进程继续运行 | 进程树终止与完成确认 |
| 身份泄露 | 路径、日志、提交材料包含个人信息 | 相对路径、双盲扫描、提交前人工审查 |

## 5. 工作区隔离

### 5.1 根目录

启动时必须：

1. 接收显式 `--workspace` 或使用当前目录；
2. 解析为绝对、规范化路径；
3. 确认目录存在且可访问；
4. 在 Session 生命周期内固定根目录。

模型和工具的公共输入只使用相对路径。空路径按工具语义表示工作区根，不接受用户主目录缩写。

### 5.2 路径校验

文件工具执行前必须：

1. 拒绝设备路径、UNC 路径和工作区外绝对路径；
2. 将输入与根目录组合并规范化 `.`、`..` 和分隔符；
3. 按 Windows 大小写不敏感语义检查目标仍在根目录内；
4. 对已存在目标解析真实路径；
5. 对新目标解析最近的已存在父目录，再验证最终目标；
6. 在实际打开或写入前尽可能再次验证。

不能仅使用字符串前缀判断，例如 `C:\\repo2` 不是 `C:\\repo` 的子目录。

### 5.3 符号链接与目录联接

- 指向工作区外部的符号链接或目录联接一律硬拒绝；
- 递归列表不得跟随未验证链接；
- 写入新文件时必须验证其父目录真实路径；
- 首版应记录链接拒绝原因，但不得暴露外部目标的完整敏感路径给模型。

文件系统的存在检查与后续使用之间存在 TOCTOU（检查时与使用时不一致）竞态。首版通过执行前复检降低风险，但不宣称达到对抗本机恶意进程的强隔离。

## 6. 文件操作规则

### 6.1 读取

- 只允许工作区内普通文件；
- 单次读取有大小和行数上限；
- 二进制文件默认拒绝或只返回元数据；
- 截断必须标明原始大小、保留范围和截断事实。

### 6.2 写入与补丁

- 写入前必须再次完成路径与策略校验；
- 默认生成可审查的变更摘要或 diff；
- 不允许借助文件工具删除工作区根或递归删除目录；
- 不允许写入 `.git` 内部结构；
- 会覆盖既有文件的完整写入在 `safe` 模式下需要审批；
- 部分失败不得被报告为成功。

首版不提供通用删除工具。确有删除需求时，通过受策略管理的命令执行，并要求人工审批或拒绝。

## 7. 命令执行

### 7.1 启动方式

Windows 首版以 PowerShell 为受支持 Shell，并使用等价于以下的非交互约束：

```text
%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoLogo -NoProfile -NonInteractive -InputFormat Text -OutputFormat Text -Command <command>
```

实际可执行文件应通过受控配置或上述 Windows PowerShell 5.1 宿主路径发现，不得依赖 `PATH` 上的 `powershell.exe` 短名，也不从模型输入决定。stdin 以立即 EOF 的管道接入，避免 5.1 在重定向输入上等待 CLIXML。编码通过标准输出流设置，不调用会在无控制台会话中挂起的 `[Console]::InputEncoding` / `[Console]::OutputEncoding`。Windows PowerShell 5.1 的 `Set-Content`/`Get-Content` 在系统 ANSI 代码页无法表示工作区路径时可能阻塞，因此工作区 Unicode 路径以 .NET 文件 API 与 Win32 当前目录为准。子进程必须设置：

- 工作目录为规范化后的工作区目录；
- 显式超时；
- 独立 stdout/stderr 捕获；
- 输出大小上限；
- 可传播的取消信号；
- 最小化且移除敏感项的环境变量。

### 7.2 风险分类

安全策略先对规范化命令分类，再决定 `allow`、`ask` 或 `deny`。

低风险候选：

- 读取型版本与状态命令；
- lint、typecheck、test、build；
- 在工作区内列举或搜索内容；
- 不修改依赖锁文件的诊断命令。

需审批候选：

- 安装或更新依赖；
- Git 写操作、提交或推送；
- 启动网络服务或访问外部网络；
- 批量重命名、覆盖或删除；
- 执行仓库内来源不明的脚本；
- 可能长时间运行或显著消耗额度的命令。

硬拒绝候选：

- 明确访问工作区外敏感路径；
- 读取或导出凭据、浏览器数据、SSH 私钥或系统密钥库；
- 关闭安全软件、修改系统策略或提权；
- 针对磁盘、用户目录、仓库根等宽泛目标的递归破坏；
- 试图把密钥发送至模型、日志或外部端点；
- 绕过 ECHO 策略执行等价操作。

规则应关注实际效果，不只匹配单个命令名。复合语句、重定向、管道、调用运算符和编码命令需要更严格判断。

### 7.3 Shell 隔离限制

PowerShell 不是沙箱。获准执行的程序可能自行访问工作区外文件或网络，而 ECHO 无法仅靠命令文本分析完全阻止。因此：

- `balanced` 模式不自动批准来源不明或影响范围不清的命令；
- 演示目标使用受控 fixture 和已知测试命令；
- 高风险仓库应在临时目录、低权限账户或容器中运行；
- 首版 README 必须公开说明这一限制。

## 8. 安全模式

### 8.1 `safe`

- 读取型操作可自动执行；
- 文件写入、依赖变化、Git 写操作和潜在网络访问默认询问；
- 非交互运行遇到询问默认拒绝；
- 适合首次运行与未知仓库。

### 8.2 `balanced`（默认）

- 工作区内明确、局部、可审查的文件修改可自动执行；
- 常见验证命令可自动执行；
- 依赖安装、外部网络、Git 写入、删除和宽泛副作用仍需询问；
- 任何硬拒绝规则继续生效。

### 8.3 `auto`

- 可自动通过一部分原本需要询问但已被规则明确分类的工作区内操作；
- 不得关闭路径边界、密钥保护、超时、输出限制和硬拒绝；
- 必须在启动输出和事件中明确记录模式；
- 不应作为默认演示模式。

安全模式只能调整“允许”与“询问”的边界，不能把硬拒绝变成允许。

## 9. 审批模型

- 审批内容必须显示工具名、规范化目标、风险原因和可能影响；
- 用户可以选择拒绝、仅本次允许，或在当前 Session 对等价操作允许；
- Session 批准使用稳定的 `approvalKey`，不得通过模糊文本匹配；
- 参数、目标范围或命令效果变化后必须重新评估；
- 审批决定写入脱敏事件；
- CI/非交互模式不得等待隐藏式终端输入。

首版不提供永久全局白名单，避免配置误用扩大影响。

## 10. 密钥与环境变量

### 10.1 API Key

- 只从进程环境或受保护的用户级配置来源读取；
- 不写入仓库文件、项目配置、JSONL 事件或异常详情；
- 诊断只显示“已配置/未配置”；
- Provider 请求日志不得包含 `Authorization` 头；
- 不把 Key 放入模型消息。

### 10.2 子进程环境

工具子进程基于允许列表构建环境。至少必须移除：

- `ECHO_API_KEY`；
- 常见云服务、包仓库和版本控制令牌；
- 由 ECHO 内部使用的授权头或临时凭据。

为保证 Node、pnpm 和 PowerShell 可运行，可以保留 `PATH`、必要的系统目录和非敏感运行变量。`PSModulePath` 不继承用户环境，而由 `SystemRoot`/`WINDIR`（大小写不敏感）构造为系统 `WindowsPowerShell\v1.0\Modules`。最终允许列表需在 Windows 集成测试后固化。

## 11. 日志、事件与脱敏

事件写入顺序：

```text
raw runtime data -> normalize -> redact -> truncate -> persist/render
```

不得先持久化再脱敏。脱敏至少覆盖：

- 已知 API Key 与授权头；
- URL 中的凭据和敏感查询参数；
- 常见 token/key 形态；
- 用户主目录等可能暴露身份的绝对路径；
- 环境变量转储。

对外展示以相对工作区路径和随机 Session ID 为主。脱敏规则不是保存秘密的替代方案：源头不采集优先于事后替换。

`.echo/` 必须加入 `.gitignore`。提交前的双盲扫描应检查姓名、院校、用户目录、邮箱及其他可识别信息；具体清单在交付阶段单独维护，不把私密原始材料放入公开仓库。

事件存储在创建和打开 `.echo/sessions/` 及会话文件前检查已有路径组件；链接、目录联接、
非普通会话文件和解析到工作区外的存储路径均拒绝。该复检降低链接逃逸风险，但与文件工具
相同，不宣称消除本机恶意进程制造的 TOCTOU 竞态。

## 12. 输出与资源限制

- 模型 Turn 有最大 Step 数；
- 相同工具名与规范化参数连续或循环重复达到阈值时终止；
- Provider 请求和每个工具都有超时；
- stdout、stderr、文件读取和搜索结果都有独立上限；
- 截断保留头尾与定位元数据，并明确标注；
- 大输出如需临时落盘，只能进入工作区内被忽略的 ECHO 临时目录，并遵守清理与脱敏策略；
- API 重试次数和总等待时间有界。

默认阈值在性能测试与演示验证后写入配置文档。

## 13. 取消与进程清理

- Ctrl+C 或上层 `AbortSignal` 触发 Turn 取消；
- Provider 流必须尽快中止；
- 在途工具进入 `cancelled` 终态；
- 命令超时或取消时终止完整进程树；
- 清理动作有独立短超时，失败需记录诊断；
- 取消后不得继续执行队列中的后续工具调用。

## 14. Git 与外部副作用

- ECHO 首版不提供专用 Git 写工具；
- `git status`、`git diff` 等只读命令可以按模式自动允许；
- `commit`、`push`、分支删除、历史重写必须询问或拒绝；
- ECHO 不主动向远端发送代码；
- 模型服务仍会接收 Context Projector 选取的代码片段，README 必须提示用户仅在获授权代码库中运行。

## 15. 双盲与保密控制

项目有额外的材料保密和身份匿名要求：

- 原始题目、邮件和内部评分内容不得进入仓库；
- 文档只描述公开的系统设计，不复述保密考核材料；
- 示例数据不得包含真实姓名、学校、私人邮箱或本机用户名；
- 演示前在仓库、终端主题、路径、Git 输出和视频画面中执行人工检查；
- 自动扫描提供辅助证据，但最终提交必须人工复核。

## 16. 已知限制与后续增强

首版明确不提供：

- 操作系统级文件或网络沙箱；
- 对任意 PowerShell 脚本的完备语义分析；
- 对本机恶意进程造成 TOCTOU 竞态的完全防护；
- 凭据管理器或硬件密钥集成；
- 完整快照、回滚和事务式文件系统；
- 对所有第三方脚本副作用的静态证明。

后续若增加容器隔离、受限令牌、命令 AST 分析或变更快照，应通过独立 ADR 评估复杂度与收益。

## 17. 安全验收条件

本文升级为 `Accepted / 1.0` 前，至少需要自动化验证：

- `..`、绝对路径、UNC、大小写变化和链接逃逸；
- 新建文件时的父目录逃逸；
- `.git` 内部写入拒绝；
- `safe`、`balanced`、`auto` 的策略矩阵；
- 硬拒绝无法被批准；
- API Key 不出现在事件、模型上下文和子进程环境；
- 命令超时、取消和进程树清理；
- 大输出截断与明确标记；
- 重复工具调用终止；
- 双盲扫描脚本在已知测试样本上的表现。
